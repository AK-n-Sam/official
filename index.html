The system layer

The parts that keep the workspace running.

Behind the six work areas: a unified inbox, a rules engine that chases the follow-ups for you, role-aware access control, and reporting that turns the ledger into plain-language decisions.

Communications

Connected email and WhatsApp land in one inbox, threaded against the customer they belong to.

  • Unified conversation list with unread state
  • Reply and log activity without leaving the record
  • Templates for the reminders you send every week

Automations

An autopilot engine for SME busywork: rules you can toggle, run on demand, and audit afterwards.

  • Overdue invoice reminders and payment nudges
  • Low-stock alerts and reorder suggestions
  • Run history so you can see what fired and when

Team & Access

Owner, admin and member roles, workspace settings, and an audit log of who changed what.

  • Invite teammates with a scoped role
  • Record-level visibility by creator, not by guesswork
  • Bulk reassign work when someone moves teams

Business Brain & Executive Cockpit

Reporting that reads like a briefing, not a spreadsheet.

Insights start from your own ledger — invoices, payments, expenses and stock movements — and narrate the month in five questions. The Executive Cockpit adds ARR run-rate, margin and health scoring for the people who own the P&L, with a read-only mode for everyone else.

Also in the box: printable A4 invoices with PAID / OVERDUE stamps, CSV export with formula-injection guards, and a Help Center that deep-links to the topic for the page you're on.

What changed?Revenue moved 14% over the last 30 days.
Why did it change?Three key accounts completed major purchase orders.
Is that good or bad?Gross margin expanded 2.4 points — good.
What needs attention?Two invoices are more than 14 days overdue.
What should I do next?Send reminders, then follow up on three active deals.

Under the hood

Built like production software, not a slide deck.

A FastAPI + MongoDB backend with a reusable CRUD engine, a React 19 shell with a shared resource manager, and multi-tenant isolation enforced in the data layer rather than in the UI.

Multi-tenant from the first query

Every document carries an org_id; every user carries org_ids[] and an active_org_id. Switching workspace re-scopes every list, metric, chart and export — no client-side filtering to bypass.

One CRUD engine, seven modules

A single make_crud factory powers customers, products, expenses, suppliers, employees, tasks and leads — with search, filters, validation and member scoping. The UI mirrors it with one ResourceManager component.

Roles and record-level visibility

Owners see everything, admins can be scoped to their own records with an admins_see_all switch, members only see what they created. Privileged actions (invites, removals, reassignment) are gated server-side.

Auth that survives production

JWT bearer tokens plus httpOnly cookies, org-scoped get_current_user, access requests reviewed in the Admin Center, and a bcrypt-hashed user store. Admin seeding comes from environment variables.

Money that reconciles

Per-line discounts and tax, atomic invoice numbering that never reuses a number, payments that flip invoices to partially paid or paid, auto-overdue detection on read, and stock that returns when an invoice is cancelled.

A design system with rules

Tailwind + shadcn/ui on Outfit, IBM Plex Sans and JetBrains Mono. Tabular numerals on every figure, solid card surfaces (no ghosted overlays), density modes, and dark-first theming with a light switch.

Run it

Two terminals and you have a workspace.

The backend seeds a new account with three fully-populated demo workspaces in different currencies, so the dashboard has real numbers to draw the moment you sign in.

01

Have a MongoDB URI ready

Python 3.12 and Node 20 mirror CI. Copy the env block on the right into backend/.env.

02

Start the API

FastAPI on port 8001 — health check at /api/health.

03

Start the app

Point the frontend at the API and sign in with the admin account your environment defined.

bash — six6fix 
# 1 · API  (http://localhost:8001)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn server:app --reload --port 8001

# 2 · Web app  (http://localhost:3000)
cd frontend
npm install
REACT_APP_BACKEND_URL=http://localhost:8001 npm start
